Agent Autopilot 与目标模式

只要你的消息是在要求 AI 查看项目、修改文件、运行命令、排查问题或提交代码，它就会自动进入 Agent 循环，把活做完再回来，不必反复发送「继续」。目标模式是同一套循环的更严格形态：显式六阶段、80 轮强闭环。

#Agent Autopilot 是什么

Autopilot 是 SLATE 的默认执行层，不需要你手动开启。

  • 识别到查看、修复、运行、提交、项目文件一类环境操作类请求，就自动进入多轮循环。
  • 普通任务默认最多 24 轮；全面排查、项目级、多文件任务默认最多 40 轮。
  • 轮数是止损线，不是预算：交付并逐项验证通过后循环就该结束，而不是"用满 24 轮"。
  • 对话里的每一条工具调用都会变成卡片，你能看到它读了哪个文件、跑了什么命令。

#三种运行强度对比

运行强度什么时候用轮数上限是否自动建任务清单怎么退出
普通对话问答、写作、解释代码，不需要 AI 动你的文件不进入工具循环否回复结束即结束
Agent Autopilot修一个 bug、跑一次测试并修错、生成一批文件普通 24 轮；全面排查 / 项目级 40 轮复杂任务建议建，不强制模型显式收口；未收口则标为中断
目标模式多文件改造、完整排查、长链路任务80 轮会，且未了结不得宣称完成手动停止 / 轮数用完 / 清单全部了结 / 模型收口

目标模式在输入框左侧的 ＋ 菜单里开关，打开后再发消息即生效。

#循环里会发生什么

每一轮循环大致按下面的节奏推进：

  1. 观察：读取相关目录、文件、配置或 Git 状态，不凭记忆猜。
  2. 执行：调用工具推进，能合并成一批的读取与扫描会在同一轮里做完。
  3. 验证：改完必须重新读取、运行命令或跑测试，失败就继续修。
  4. 汇报：逐条核对结果、验证方式与剩余风险。

工具结果会作为隐藏上下文回灌给模型，让它接着往下走，而不是把一堆原始输出摊在你的屏幕上。

如果某一轮发出的工具调用与上一轮完全相同，系统会拦截这次重复执行并提醒它换思路——同样的动作再跑一遍只会浪费轮数。

#干完了就停

Autopilot 不接受"说到一半就停"：

  • 模型必须显式收口（你会看到一次收口调用）才算真正干完。
  • 没走完成通道就退出（轮数用完、空转、你点了停止），状态会如实标成「已中断 · 任务未确认完成」，并在消息区给出「继续跑完」入口。
  • 「继续跑完」不会重头再来，它从断点接着推进。

#自动催办

模型话说到一半不动手时，系统会主动催它：

  • 只说"我将检查 / 接下来修改 / 是否继续"这类前瞻计划，且没有发起任何工具调用——催它直接调工具。
  • 没有执行任何工具却口头说"已完成"——要求它先验证，或者真正动手。
  • 连续多轮只描述计划不执行——给出更明确的警告，必要时提前止损，避免空耗额度。

这些催办只加进发给模型的上下文，不会占用你的消息区；哪怕中间发生过上下文压缩，它们也不会变成一条冒出来的气泡。

#Continue Autopilot

轮数用完不等于干完。Continue Autopilot 默认开启，在「设置 → 自动推进」里可以关掉。

  • 最后一轮模型还在动手：把上限往后推 8 轮，让它把手上的活做完。最多追加 3 次，不会无限续跑。
  • 最后一轮模型空手停笔：把任务清单里剩下的项目念回给它，催它继续推进，或明确回复【任务完成】。

推完 3 次还是到了上限、这一场并没有自己收口时，散场之后不必再手动点：只要这场不在手动审批档（自动审批 / 完全访问 / 夜间模式），SLATE 就替你按下「继续跑完」。它会等这一场真正空下来——压缩与记忆蒸馏这些收尾还要占着这场几秒——再发那句「继续」，一场最多自动续 2 次，并给一句「轮数用尽 · 已自动续跑（第 1/2 次）」的回声。手动审批档不自动按：那一档的语义就是每一步都要人点头，它只把「继续跑完」条挂在消息区等你。额度用尽或自动续没接上时，那颗手动按钮仍在原地，从断点接着推进，不会重头再来。

追加轮数有上限

追加只放宽上限，不会取消止损线。若任务本身需要更长的闭环，直接开目标模式，而不是靠反复追加。

#砚流：落笔即所见

模型逐个 token 写工具参数时，砚流会按工具的参数结构实时推断哪些字段已经写完、正在写哪个字段，把参数成形的过程演成一行可见的预览。

  • 它只做预览：半成品参数永远不会触发执行。
  • 正文类字段（文件内容、Markdown、HTML 等）一律折叠成行数与字数，不会刷屏。
  • 参数很短的工具不会起笔动画，避免无意义的闪烁。

#停止是真取消

点「停止」不只是让界面安静下来：

  • 同时关闭模型流与工具调用的流式通道。
  • 后端随之终止对应的子进程与在跑任务。
  • 被取消的调用以独立状态记账，与「已完成」分开统计，事后可以回溯这一笔是停的还是做完的。

#本轮改了哪些文件，说完就摆出来

这一轮真的往磁盘写过文件（编辑 / 新建 / 追加）时，模型说完最后一句话后，消息末尾会挂出一张卡片。它只报事实，不替模型表功。

  • 抬头是这一轮改了几个文件、各自行数增减；点「审阅」逐文件展开 diff（默认列三条，其余点一下再显示）。
  • 点「撤销」把这一轮写过的文件还原成本轮开始之前的样子，本轮新建的文件一并删掉；执行前先过一道红色确认。
  • 你在本轮之后又自己改过的文件会被跳过并写明原因——撤回只还原它自己写过的那份，不吃掉你自己的修改。
  • 本轮没往磁盘写任何东西时不留卡片；关掉了自动应用也一样：那次写入仍然记在它提出那一轮的清单里，但要等你点「接受」之后才真的落盘。
  • 原文快照存在 data/round_snapshots/，只保留 7 天；超过 2MB 的大文件不存原文，撤回时会跳过并说明。全部留在本机，不上传。
  • 移动端只展示这份清单，撤销留在桌面端做。

#目标模式

目标模式是显式的强闭环模式：你给目标，模型按六阶段自主推进。

#六阶段闭环

目标 → 计划 → 执行 → 验证 → 汇报 → 追溯。

  • 每轮工具结果都会标注当前轮次（第 x/N 轮），模型据此把握剩余节奏。
  • 停止只中断当轮，目标模式开关保持开启待命，随时可以接着跑。

#任务清单

  • 多文件、多步骤、排查或实现类任务会自动建立任务清单；简单单步任务可跳过。
  • 清单在消息区右侧栏实时展示，顶栏的「任务清单」按钮可以随时折叠它，把宽度还给消息区。
  • 折叠后按钮上仍报 {done}/{total} 进度，这场没有清单时按钮置灰。
  • 未全部了结，模型不得宣称完成；每完成一批立即回写状态。

#四种退出方式

目标模式只有这四种退出路径：

  1. 你手动点停止。
  2. 80 轮用完。
  3. 清单全部了结。
  4. 模型显式收口结束循环。

模型侧失败、零输出、重复调用都会自动恢复推进，不会因为一次异常就中断整场。

什么时候该开目标模式

当任务需要"改完还要验证、还要回头补"的完整闭环时才开：多文件重构、全项目排查、需要边跑边修的长任务。只改一个文件、问一个问题就别开，目标模式会为建立和核销清单多花掉几轮预算。

#输出截断四层防线

写超长文件时模型可能被输出上限截断，SLATE 用四层防线保证文件最终是完整的：

  1. 断点锚点续写：把模型自己最后输出的内容作为锚点，让它从断点精确接续（最多 6 轮）。
  2. 截断守卫：工具调用没闭合就拒绝执行，要求模型拆分重试，而不是写进半份文件。
  3. 分段补齐：先用创建写入前半部分，再用追加动作把剩余部分补齐，卡片上会标出这一段是截断的、等待后续补齐。
  4. 提示词预防：在提示里事先要求它分批写入大文件。

#一整轮只有思考、没有正文

还有一种截断跟文件无关：思考过程与正文共用同一个输出上限，思考吃满时这一轮就没地方写正文了。这类结局 SLATE 会如实报出来，不再让它悄悄过去：

  • 流收到内容后自然结束、却既没有结束标记也没有结束原因时，这一轮会被标记。
  • 收尾时分开说明是「思考占满输出上限」还是「上游提前中断」，并给出可点的「继续」入口，从当前上下文接着跑。
  • 正文有内容但流提前断掉的，标注为可能不完整。
  • 这套提示与「继续」入口在任何模式下都给，不只是自动推进模式——否则关掉自动推进时，就只剩「它自己停了」这一种解释。

#跨项目并行

切换项目不再打断正在生成的对话：你离开的那一场会在后台继续跑，进度与结局落在右栏的任务中心。

  • 同一项目内默认串行（两场同时改同一批文件坏了难查是谁写的）。
  • 跨项目最多两场同时运行，可在「设置 → 多任务与项目」里调到 1–4。
  • 超出上限的发送不会被吞掉，而是进队列并标出「排队中」，前一场一收工自动接上。
  • 每条会话的 Token 各记各的，用量条只反映屏幕上这一场。

项目与工作区的组织方式见 项目、工作区与分项目配置。
