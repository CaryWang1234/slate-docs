白板式逻辑链

想不清楚的时候，把东西摆出来看。白板让你把灵感、功能与待办写成卡片，用连线标出依赖与数据流；它同时还是这场对话的仪表盘——工具跑到哪一步、这一场怎么控制，都能在同一屏看到。

#白板用来干什么

三件事：

  • 把想法外化：想到什么先落成一张卡，不必先排序，之后再连线整理。
  • 看清依赖：连线表示「谁依赖谁」「数据从哪流到哪」，箭头方向就是顺序。
  • 当运行现场：工具执行会自动留下步骤卡，工作流视图还能就地控制这一场对话怎么跑。

白板与当前对话是联动的：团队辩论可以读到板上的卡片当背景，你也可以把墨稿投到白板上推演。

#基本操作

顶栏「黑板」进入，默认就是自由画布。

  • 新建卡片：顶栏「＋」按钮，或在流程视图里点「根卡」新建一个流程起点。
  • 移动布局：直接拖动卡片。顶栏的「自动整理布局」会按连线关系分层排布（快捷键 Ctrl + L）。
  • 编辑卡片：双击卡片打开编辑弹窗，可改标题、正文、颜色与连线关系。
  • 多选：按住 Shift（或 Ctrl / Cmd）点击可加选与减选，多选后可用 Ctrl + D 复制、Delete 删除。
  • 连线：把工具切到「连线」，先点起点卡片再点终点卡片。连线就是依赖与数据流。
  • 画笔与文字笔记：工具栏可切到画笔随手画，「文字」模式下在空白处点一下即可写一条笔记。
  • 收起画笔痕迹：「撤销笔画」撤销最后一笔，「清除所有笔」一次清空。
  • 导出与清空：顶栏可导出整块黑板（卡片、关联、颜色、Mermaid 源码与 JSON）；「清空黑板」会清掉所有卡片，按提示确认后再动手。

按 Esc 可随时取消选择并切回「选择 / 移动」工具。

#卡片颜色就是它的分类

颜色不只影响观感，看板视图与 AI 整理都按它分类：

颜色含义
默认未分类
红色风险
橙色待处理
黄色想法
绿色完成
蓝色信息
紫色创意

拿不准就先放默认，整理的时候再统一染一遍色——看板视图里换列就是换颜色。

#跟对话、团队、墨稿的联动

白板不是一张孤立的图，它和几处能力是通的：

  • 模型可以直接读写白板：读取现有卡片、新增卡片、更新标题与正文、改依赖、改颜色，还有批量操作与清空。所以你可以直接说「把这几个想法整理成卡片并连上线」，它会动手摆。
  • AI 整理成流程图：顶栏的整理按钮会把卡片标题、正文、依赖与颜色整体重构一遍，原有卡片 ID 保持不变。它属于「设置 → AI 辅助功能」里的「黑板 AI 整理」，可以单独关掉或指定模型。
  • 团队辩论会读白板：发起团队讨论时，当前板上的卡片会作为背景资料交给各成员，让它们围绕你已经写下来的东西讨论，而不是重新猜。
  • 墨稿可以投过来：磨墨模式收墨后，点「投到白板推演」就能把任务书铺成卡片继续推演，见 磨墨模式。

#Mermaid 实时渲染

卡片与连线会自动生成一段 Mermaid 图（方向从左到右），并由 Mermaid.js 实时渲染成流程图。顶栏的图表按钮可以显示或隐藏这块渲染区；图随卡片改动即时重画。

如果渲染失败（例如卡片标题里有特殊字符），面板会就地提示失败原因，不会影响白板本身。

#六种显示模式

顶栏有五个视图按钮，再加上默认的自由画布，一共六种看法。再点一次当前选中的按钮就回到自由画布。

模式看什么什么时候用
主黑板（自由画布）卡片、连线、画笔、文字笔记发散整理，随手摆
流程按依赖层级分阶段列出卡片，每张标出输入与输出条数看清先后顺序与合流点
看板按卡片颜色分列，拖进另一列即改分类按状态推进一件事
纲要以连线为层级展开的树，可逐层折叠长清单、层级结构
Git 树当前打开项目的仓库结构摸清分支、提交与工作区状态
工作流控制条 + 流程卡片墙 + 当前运行 + 团队星图边跑边看

流程视图与看板视图里都带「排布」按钮，能把当前视图的层级或列顺序同步回画布。纲要视图会把没有连线的卡片单独列在「未连接卡片」下，提醒你还有孤立的想法。

#Git 树视图

需要先打开一个项目，Git 树读的就是这个项目仓库的状态。它会识别并画出来：

  • 仓库本身、HEAD、当前分支、本地分支、远程分支、标签与 remote。
  • worktree 列表，以及 stash。
  • 工作区的三组计数：已暂存、已修改、未跟踪（各带文件数量，没有变更就写「无变更」）。
  • 未推送的提交，以及最近的提交记录。

节点位置和整个视野都可以拖动，摆好的位置会记在本机，下次进来还是你摆的样子。没有打开项目时它会直说，而不是画一张空图。

#工具步骤卡自动记录

每次工具执行都会自动在画布上生成一张步骤卡，你不必手动记。

  • 卡片标题形如「步骤 N：<这一步在做什么>」，正文写这一步的参数摘要，跑完后换成结果摘录。
  • 颜色标状态：黄色 = 执行中，绿色 = 完成，红色 = 错误，已取消是默认灰色。
  • 卡片之间会按调用顺序自动连成一条链。
  • 状态变化只回写卡片正文与颜色，编号与位置不动，所以正在跑的时候整块板不会乱跳。
  • 新一轮运行开始时，上一批步骤卡整批清掉，板上只留这一轮的。

在流程、看板、纲要这三种视图里，步骤卡默认是隐藏的，右上角的「显示工具步骤」可以把它们切出来看。

步骤卡是被动产生的

它记录的是「这一场实际调用了什么」，不吃 Token，也不占提示词预算。想看工具到底干了什么，看这里最可靠。

#工作流视图：一屏四块

切到「工作流」模式，这一屏同时是控制台和现场。

控制条：停止、继续跑完、自动推进（目标模式开关）、回复模式（内置四档 + 自定义，可选任意一档）、思考强度（自动 / 关 / 低 / 中 / 高）。可选档位按当前模型的能力给出，上游不认的档位不会出现。这些控件不另存一份状态——它们写的就是聊天框顶部那套状态，两处永远不会不一致。旁边还有「去团队」按钮，直接跳到团队模式。

流程卡片墙：每一份 Action 流程说明书一张卡，卡面写着共几步、几项输入、谁写的（你写的 / 模型写的）、产出落到哪，以及标签。「跑这条」以 @提及 的方式把它发进当前对话，「看步骤」就地展开步骤清单，「置顶」把常用的排在前面（配合「只看置顶」把卡片墙收窄）。说明书解析失败时，这里会给出提示。写说明书的方法见 Actions 流程说明书。

当前运行：直接从运行记录投影出来——哪一步在跑、跑了多久、成没成。没有记录时它会说明白：本场还没有运行记录、或者本轮还在思考尚未调用工具。

团队星图：按角色摆出这场对话最近一次团队讨论，谁回应了谁、各自动过哪些工具、派生了哪些子代理，全部取自真实记录。点一位成员可以看它最近的发言序列。这场对话没有团队记录时，它会直说，不会画一张装饰性的图。

#思考过程显示

模型在动手前的推理与思考过程会实时显示在一个可折叠面板里，思考完成后自动折叠，点标题栏可以再展开回看。它单独成一块，不会混进正式回答里。

白板内容会留在本机

卡片、文字笔记、画笔笔画、Git 节点位置以及工作流视图的置顶偏好，都保存在你这台机器上，刷新与重启之后还在。它们不随对话走，也不会被别的项目覆盖。
