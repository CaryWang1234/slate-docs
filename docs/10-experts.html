专家包

每换一个场景，你都要重新交代「你是谁、按什么规矩来、参考哪些资料」。专家包把这些收进一个文件夹：装一次，之后按需挂上，模型就以这位专家的身份和口气干活。

#专家包是什么

专家包是一份可分发的角色配置：一个人怎么想、守什么规矩、知道什么、会哪些方法，全部打包在一个文件夹里。它可以只在你本机用，也可以压成 zip 分享给同事。

装载之后不写进对话历史，而是作为系统提示的一部分注入——所以换会话、换模型都还在，直到你把它摘下来。

#五件套结构

一个专家包由五个部分构成：

部分作用该写什么
persona.md人格：这位专家是谁身份与经验、擅长解决什么、说话与思考的风格
rules.md规则：必须遵守什么判断口径、输出格式要求、绝不允许的做法
knowledge/知识：他掌握的资料真会用到的资料摘录，一个主题一个文件
skills/技能：他会哪些方法步骤化的方法论、检查清单、模板
data.json元信息名称、一句话描述、版本、作者

knowledge/ 与 skills/ 都是文件夹，可以放多个文件，文件名就是它的标签。

persona.md 决定「像不像那个人」，rules.md 决定「稳不稳定」。如果只写一份，优先写 rules.md——人格让表达有味道，规则才是让它每次都能交付的东西。

#从零做一个专家包

在专家包管理面板里点「新建」，然后按顺序填：

  1. 写名称与描述：名称是它在各个下拉框里显示的名字，描述是一句话说明，都会随包一起导出。
  2. 写人格（人格页签）：这位专家是谁、擅长什么、用什么口气说话。写短句，写具体。
  3. 写规则（规则页签）：它必须怎么做、绝不允许怎么做、输出成什么格式。
  4. 放知识文件（知识页签）：逐个上传，文件名就是它的标签，比如「判断口径.md」「常见坑.md」。
  5. 放技能文档（技能页签）：把你常用的方法论、清单、模板放进来。
  6. 保存：保存后立刻生效；想给别人用，点「导出」存成 zip。

#规则怎么写才有效

规则不是口号，是可执行的约束。与其写「请专业一点」，不如写清「必须做什么、不许做什么、输出成什么样」。一份能用的规则大概长这样：

text
## 输出要求
- 先给结论，再给理由，最后给可执行的下一步。
- 涉及数字时注明来源；没有依据就写「无数据」，不要估算。

## 检查口径
- 每条建议都要写清适用条件与代价。
- 结论有前提时，把前提写在结论前面。

## 禁止
- 不使用「可能」「大概」这类含糊表述来回避判断。
- 不引用未在资料中出现的案例或数据。

把它作为参照：条目越具体、越像检查清单，模型的执行就越稳定。

#导入与导出

导出为一个 zip，导入也是同一个格式，可以直接发给同事。

  • 导入的包必须包含 persona.md、rules.md 与 data.json 三个文件；这三者允许放在 zip 内的单一根目录里。
  • 一个包的上限是解压后 50 MB、最多 500 个文件。
  • 导入进来的是本机的一份副本，改它不会影响别人手里的原件。

在专家包管理面板里点「导入」选 zip，点「导出」把当前这位存成 zip。

先用内置样例体会一下再自己写

SLATE 自带一个样例包「创意写作导师」，装好就能用。先拿它试一次对话，看看人格与规则的注入效果长什么样，再照着它的写法拆出你自己的专家。

#内置样例：创意写作导师

样例包的名字是「创意写作导师」，定位是「帮助你把灵感打磨成故事的叙事专家：提供结构诊断、文风建议与具体改写示范」。

它的五件套里带了两个知识文件与一份技能文档，可以直接拿来当模板：把 persona.md 换成你的角色，把 rules.md 换成你的口径，知识文件换成你手上的资料。

#三路注入的区别

同一份专家包，可以从三个地方挂上去，生效范围完全不同：

注入方式在哪选生效范围注入什么
对话输入区的专家下拉对话输入区左侧这场对话全程生效人格 + 规则 + 知识文件的名字清单
团队成员卡团队模式里每位成员的「专家包」下拉只对这个角色的发言生效人格 + 规则
聊天 @ 提及在输入框输入 @ 选专家包只对这一条消息生效人格 + 规则 + 前 6 个知识文件的正文（每个最多 4000 字符）

区别的关键在最后两列：前两路只给知识文件的名字，模型知道「有这个文件」但不一定读得到内容；只有 @ 提及那一路会把知识正文塞进这条消息，代价是这条消息的 Token 明显变大。

所以用法可以这样分工：要一个稳定的专家身份，用下拉框挂着；要它这一次真的翻某份资料，用 @ 提及。

#什么时候该用专家包

  • 跨多次会话、反复做同一类事：例如长期做技术方案评审、长期写对外文案。
  • 有明确口径与禁忌：这些写进 rules.md 比每次口头强调更可靠。
  • 要分享给别人：一个 zip 就是全部，收的人导入即可复现。

反过来，如果只是这一次想让它的口气变一变，直接在消息里说清楚就够了，不必专门建一个包。

#维护与更新

  • 改完就生效：在面板里保存后，如果这个包正挂在这场对话上，注入的内容会同步更新，不必重新选一遍。
  • 文件可增减：知识文件与技能文档都可以随时上传和删除，删掉的会从名单里消失。
  • 删除不可恢复：删掉一个专家包时会有一次确认，确认后无法撤销；想留底就先导出一份 zip。
  • 建议留一份备份：手写的规则与整理好的知识资料都是心血，导出的 zip 就是最简备份。

#注意事项

  • 知识文件越大越费 Token。@ 提及最多读 6 个文件、每个截到 4000 字符，装得越多，每条消息的固定开销越大。
  • 建议只放真的会用到的内容：一份「常用判断口径」比一本「素材全集」有用。
  • 规则与人格要短而具体。写成大段散文，模型反而抓不住重点；用短句与清单写得越明确，它执行得越稳定。
  • 一个包尽量只覆盖一类角色。需要多个角色时，做多个包，用团队模式分别挂上去更清楚（见 AI 团队与工作流）。
摘不掉就换一个

专家包挂在对话上是全程生效的。发现它的口径不合现在的任务，直接在下拉里切回「无专家」，别在同一场对话里硬掰——两种口径混在一起，模型会左右为难。
