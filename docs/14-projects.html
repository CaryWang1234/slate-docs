项目、工作区与分项目配置

#项目是什么

SLATE 把"一个文件夹"当作一个项目来看待与操作。打开一个目录之后，文件树、Git 信息、终端的工作目录、代码搜索的范围都跟着它走。

项目的身份跟着文件夹的绝对路径走：同一个文件夹重新打开会回到同一个项目，会话、宪法、现场（上次停在哪条会话、草稿、看板、默认模型）都还在，历史不会散成两堆。

#打开、在册与切换

  • 顶栏项目栏的「打开项目…」按钮打开弹窗：上面是「在册项目」清单，开过的项目都留在这儿，点一下就回去，接着上次的会话和草稿继续；下面是目录路径输入框与磁盘快捷选择。
  • 打开后，项目栏显示的项目名本身就是切换器：点一下弹出「在册项目」，可以切到别的项目、把常用的固定、或从最近移除（移除只摘索引，不删除任何文件与会话）。
  • 项目栏的 × 是收起当前项目，不是删除：它仍留在在册清单里，会话、宪法、磁盘上的文件都不动，从项目名处随时切回。
  • ↻ 重新打开并刷新当前项目；工作区会重开它的宿主目录。
  • 在册项目数量有上限，到顶时先淘汰最久没打开过的归档项，固定项永不淘汰。

#项目栏与文件树

项目栏里另有三颗按钮：Better Project Understanding、Code Review、项目设置（直接跳到设置页的宪法区块）。

左侧文件树支持逐层进入、面包屑回跳与「..」返回上级；点文件就地预览，预览头上的 ＋ 会把内容片段插入聊天输入框，插入前会截取一段，避免一次灌入整份大文件。

#工作区：一个项目收进多个文件夹

有些工作本来就跨目录：前端一个仓库、后端一个仓库、文档又一个目录。工作区让它们在同一个项目里出现，而不必来回开项目。

  • 在「打开项目」弹窗里填名称、一行一个文件夹路径，点「新建工作区」。
  • 成员目录显示为文件树上方的胶囊：点一下切成当前工作文件夹，胶囊上的 × 从工作区移除（磁盘上的文件不动），＋ 把一个文件夹加进来。
  • 项目名旁会挂一个「工作区」徽标，悬停能看到包含几个文件夹、当前是哪一个。

为什么同一时刻只在一个根上工作：文件写入、Git 操作、终端命令都需要唯一确定的落点。如果同时"在多个根上"，一次 git status 或一次文件写入该落在哪儿就成了碰运气。所以工作区收的是视野，不是并发——切换当前根只需要点一下，但任何时刻的动作都清楚地落在你选中的那个目录上。

#分项目宪法

宪法是给模型的项目规则（技术边界、代码规范、架构约束）。它可以只属于某一个项目：

  • 打开着项目时保存宪法，会写进这个项目的 .slate/config.json，只对这个项目生效；它跟着仓库走，交给同事也还在。
  • 项目里没写宪法时，回落全局那份。两份各存各的落点，谁也不覆写谁。
  • 设置页宪法框下方那行字会写明这次改的是谁：「正在编辑项目「X」的宪法……」或「正在编辑全局宪法……」。提示词工厂右侧的「项目宪法」读的也是当前生效的那份，见 提示词工厂。

字段名与格式：

json
{
  "rules": [
    "改动必须保持现有代码风格，不做顺手重构",
    "新增依赖前先确认项目里已有等价实现",
    "提交信息用中文，一行说清动机"
  ]
}

rules 是一个字符串数组，每条一句话。没有 rules 或数组为空时不注入任何规则。内容不是合法 JSON 时保存会被拒绝，并提示你格式不对。

#分项目覆盖：Actions、知识库与 MCP

与宪法同一个口径：全局一份打底，项目里那一份覆盖它。三件事的覆盖粒度不同：

覆盖对象覆盖粒度项目里放哪儿怎么摘掉覆盖
Actions 流程说明书同 id 顶掉：项目里放一份同名流程，本项目用这一份；全局那份在别的项目照旧.slate/actions/<id>.yml删掉项目那份，即回到全局
知识库同标题顶掉 + 合并：项目那批排前面并顶掉同名全局文档，全局其余照旧可见归属记在知识库里，不进你的仓库删掉项目那条知识
MCP 服务器掩码：只记这台开不开、哪些工具准用，不改全局配置.slate/config.json 的 mcp.servers摘掉掩码，即回到跟全局

列表与编辑器都会标明你面对的是哪一份：项目那份带「本项目」徽标，编辑器里写明"现在改的是哪一份"。Action 编辑器里还有「在本项目另存一份」，把手上的全局那份另存为项目覆盖版；改的是项目那份时，删除按钮会说「摘掉覆盖」，并提示摘掉后本项目回到全局那一份。

MCP 的地址与密钥绝不进仓库

项目的 .slate/config.json 里只记这台服务器开不开（以及可选的工具白名单），地址与密钥始终留在 SLATE 本机的 MCP 配置里：

json
{
  "mcp": {
    "servers": {
      "my-server": { "enabled": false },
      "another": { "enabled": true, "tools": ["search", "fetch"] }
    }
  }
}

tools 不写或为空表示全部放行。把整个仓库推到远端，也不会带上任何 URL 与密钥。

#Better Project Understanding

新接手一个项目时最费时间的不是写代码，而是搞清"这堆目录到底怎么运转"。这个功能让 AI 按预算读一遍项目，产出两份文档：

  • 导览·百科：项目概述、技术栈、目录结构解读、核心模块、入口与启动方式（详细档还会梳理数据流与调用链）。
  • 规则手册：技术边界、代码规范、架构约束、运行与构建命令。每条规则都要求从项目里真实存在的证据推导出来，写成可直接执行的祈使句。

扫描预算是三档：

档位目录树深度精读文件输出规模
简略2 层6 个关键文件约 900 字
平衡3 层16 个关键文件约 1800 字
详细5 层36 个关键文件约 3200 字

精读按优先级挑选：README、依赖清单与构建配置、核心入口文件优先，同级取路径更短的，避免深层生成物挤掉入口文件。生成过程可随时取消；只依据扫到的证据写，无法确定的内容会明确标注"待确定"。

结果持久化在项目的 .slate/config.json 里，下次打开项目直接就能看，不必重新生成。两份文档可切换查看、单独复制，也可以换档位重新生成。这一档是全表里最贵的 AI 功能，可以在 设置 → AI 辅助功能 里关掉，或单独指定一个便宜些的模型。

#Code Review

Code Review 读 git diff，让 AI 从四个维度做结构化审查。取 diff 有三种方式，适合不同场景：

模式读什么什么时候用
未暂存变更工作区里改了但还没 git add 的内容提交前自查手上这一批改动
已暂存变更已经 git add、准备提交的内容把关即将进入提交的那一批
提交范围指定起点到终点（终点默认 HEAD）之间的提交复盘一次提交或一段分支上的几笔改动

四个审查维度：代码质量（命名、风格、逻辑、重复、错误处理）、安全性（注入、敏感信息泄露、认证授权、输入处理）、性能（复杂度、无谓计算、内存风险、N+1 查询）、可维护性（耦合、接口设计、注释、测试暗示）。结果有三种视图：

  • 完整报告：总体评价 + 四个维度的分析，Markdown 排版。
  • 行级评论列表：按严重程度排序的卡片，严重程度分「严重 / 重要 / 建议 / 信息」四档；点卡片上的 文件:行号 会把定位复制到剪贴板，方便你回到编辑器里跳过去。
  • 四维度卡片：四个维度并排，各自摘要与相关评论条数。

报告可以整份复制；换模式或换范围重新审一次即可。前提是这个目录确实是 Git 仓库并且有变更——不是 Git 仓库会直接告诉你，没有变更则明说"无需审查"。变更过大时会截断，并在摘要里提示。所用模型可以在 设置 → AI 辅助功能 → 代码审查 里单独指定。

#跨项目并行运行

切换项目不再打断正在生成的对话。相关设置都在 设置 → 多任务与项目：

设置默认说明
切走会话时让它继续跑开离开的那一场在后台继续，进度与结局落进右栏任务中心；关掉即旧行为：切换会话就中断这一场
同时最多跑几场2跨项目并行的总上限，可选 1–4
同一个项目内最多几场1同项目默认串行，可选 1–3

超出上限的发送不会被吞掉：它会进队列，输入框上方与右栏任务中心都会写明「排队中」以及还有几场在等，前一场收工后自动接上。停止按钮在任何设置下都只停屏幕上这一场。

后台那一场用它自己的项目现场干活——文件、终端、宪法、知识库片段都按它所属的项目走，不会写进你现在正看着的那个项目。每条会话的 Token 各记各的，用量条只反映屏幕上这一场。

什么时候用全局，什么时候写进项目

写进项目：只对这一个仓库成立的规则、流程与知识——"这个仓库用 pnpm""改前必须先跑 lint""这套部署脚本的坑"。它们跟着代码走，换机器、交接同事都还在。

留在全局：跨项目成立的东西——你偏好的表达方式、通用工作流、常用的资料摘录。全局那份是所有项目的兜底，项目里没写时就用它。

判断方法很简单：把这份内容复制到另一个项目里用，会不会产生误导？会，就写进项目。
