记忆、画像与知识库

#为什么要有记忆

每开一条新对话就重新交代一遍"我用 Python 和 TypeScript""这个仓库不吃顺手重构""回答别写长篇铺垫"——这本身就是损耗。记忆与知识库把这类信息从"每次重复说"变成"一次沉淀、长期复用"：SLATE 在对话中自己攒下要点，下次开口之前就已经知道背景。

本页讲四件事：长期记忆怎么来怎么改、用户画像是什么、灵光捕获了什么、知识库怎么按归属分家。

#记忆面板在哪

顶栏的「记忆与画像」按钮打开同一个面板，里面四个标签页：

标签页管什么
长期记忆逐条沉淀下来的要点，可增删改
用户画像角色、风格、技术栈等结构化信息
知识中心知识文档的检索、添加与归属
文库Markdown 笔记，支持 [[双链]]、标签与反向链接

手机上在底部「记忆」Tab 里管理长期记忆，详见 移动端遥控与局域网访问。

#长期记忆：攒下什么、怎么来

  • 对话中自动沉淀：每轮回复结束后，SLATE 会静默读一遍最近的对话，把值得长期保留的信息提炼成记忆条目——你的偏好、做过的决策、项目背景、术语约定、明确约束。
  • 手动添加：点「+ 添加记忆」写一条，并选一个分类。
  • 从对话提取：点「从对话提取」，把当前这场对话整理成候选记忆。
  • 自动去重：内容相同或高度相似的记忆不会被重复添加，提取结果会告诉你跳过了几条。

分类可选：偏好 / 决策 / 项目 / 术语 / 事实 / 通用 / 其他；另有架构 / 技术 / 规范 / 构建 / 日志 / 配置，供知识型条目使用。分类只影响整理与检索，不影响是否被用上。

记忆存在本机、跨会话持久化。每次对话都会把最近一批记忆和用户画像附加到上下文里，所以换一条新对话不必重新交代背景。

什么内容值得沉淀
  • 长期成立的偏好与习惯：「回答先给结论」「别自动提交」
  • 已经拍板的决策，以及当时的理由
  • 项目独有的背景、术语、目录约定
  • 明确划出的边界：「这个仓库不引入新依赖」

一次性的任务、临时状态、寒暄、工具原始输出、纯代码片段都不值得记——自动提炼时也会把它们过滤掉。

#记忆的修正与清理

信息会过时，记忆也得能改。三条路径：

  1. 自动覆盖与删除：如果对话里你明确修正、推翻或废弃了某条已有记忆，提炼时会把那条改写成新内容（覆盖，条目本身留着），或直接清掉（删除）。每次提炼的结果会如实报出"新增 / 覆盖 / 删除 / 跳过重复"各几条。
  2. 手动提炼一次：点「自动提炼画像」立即跑一次，不必等下一轮对话。
  3. 逐条编辑：双击记忆内容改文字，点笔形按钮改分类，点 × 删除。删除会同时清掉它在知识库里的那份镜像文档。

修正过的记忆立刻参与后面的对话，不需要新开一条会话。

#用户画像

画像是记忆里更结构化的一份：它不记具体某句话，而是描述"你是谁、你习惯怎么协作"。

字段填什么
角色 / 职业全栈开发者、产品经理……
工作风格注重细节、快速原型、迭代式推进……
技术栈偏好Python、React、TypeScript……
沟通习惯简洁直接、多用示例……
其他任何你希望 SLATE 提前知道的信息

画像由对话与记忆自动提炼，通常只需新增或修正个别字段；也可以手填后点「保存画像」，「重置画像」会清空全部字段。它和长期记忆一起自动附加到每次对话里，并明确要求模型不要向你复述这些内容。

#记忆怎么进入对话

记忆与画像不需要你手动"挂载"：每次发送消息时，SLATE 会挑出最近的一批长期记忆与用户画像，附加到这次对话的上下文里，并要求模型拿它们调整风格与内容，而不是当成话题复述。知识库走的是另一条路——只有开启自动检索、并且确实与当前问题相关时，命中的片段才会被注入，见下节。

三个实际含义：

  • 记忆不是越多越好：附加时会做长度截断，啰嗦的条目会挤占上下文预算。值得的留下，过期的清掉。
  • 记忆是全局的：它不随项目切换而变，进到哪个项目里都还在（知识库则按归属分家）。
  • 画像优先于纠正：填一次"技术栈偏好是 TypeScript"，比在每条对话里纠正模型省事。

#灵光：对话里值得留下的洞察

「灵光」是对话结束时的一次自动收割。切换会话时，SLATE 会判断上一场里有没有真正值得跨对话复用的技术洞察——

  • 重要的技术决策：选了什么方案、为什么、权衡了什么
  • 非显而易见的问题解法
  • 可复用的代码或架构模式
  • 关键配置与环境设置的发现
  • 值得记下来的工程经验教训

命中的内容会归档成一条标题形如「灵光 · 某某」的知识文档，参与后续的检索注入；普通问答、闲聊、工具输出、临时调试不会被收走。捕获到内容时会提示收了几条。这条链路可以在 设置 → AI 辅助功能 → 对话洞察捕获 里关掉。

#知识库

知识库是"按需检索"的那一层：不常驻上下文，只在相关时把片段注入。

  • 添加：点「+ 添加知识」填标题与内容，支持 Markdown。
  • 检索：勾选「聊天时自动检索知识库」，旁边的「片段」决定每次最多注入几条（1–12，默认 5）；也可以在搜索框里按关键词当场搜。
  • 来源：手动添加的笔记、长期记忆的镜像、灵光捕获的洞察、团队工作流产出的成果会陆续汇进来。
  • 按归属分家：开着项目时添加知识，会先问你「存进本项目」还是「存为全局」。同名（标题忽略大小写与首尾空白）时项目那条顶掉全局那条，全局其余照旧可见；别的项目的文档不会进入当前视野。完整规则见 项目、工作区与分项目配置。
  • 删除：在项目视野里删不掉全局那份（那会带走别的项目共用的文档）。先收起项目，回到只有全局的视野里删。

#文库

面板的第四个标签页是文库：一个 Markdown 笔记库。文件夹与笔记树形排列，左侧写源码、右侧实时预览。笔记可以打标签（逗号分隔），也可以用 [[笔记名]] 建立双链；选中一篇时，底部会列出反向链接——哪些笔记提到了它。搜索框按标题找，标签栏按标签过滤。适合放那些"想留着，但不适合塞进知识片段"的长资料。

#Token 成本与开关

记忆蒸馏、对话洞察、上下文压缩这些动作本身也要调用模型，所以它们都在「设置 → AI 辅助功能」里挂号：逐项可关，也可以单独指定一个更便宜的模型。与记忆相关的三档是记忆自动蒸馏、记忆手动提取、对话洞察捕获。关掉即一次模型都不发。详见 设置与安全审批。

关掉之后

关掉自动蒸馏不影响已经攒下的记忆，也不影响手动添加与编辑，只是不再自动新增、覆盖或删除条目。已经入库的知识与灵光照常参与检索。
