提示词工厂

#提示词工厂干什么

把一个已经想清楚的任务，整理成一份可以直接粘给外部 Coding Agent 的 Prompt：上下文、项目规则、约束、交付要求各就各位，不必每次从头手写。

SLATE 在这里的角色是组织者，不是执行者：它负责把上下文与约束摆好，真正的代码修改交给外部工具去做。

#界面上有哪三块

区域有什么你怎么用
左侧工作台目标 Agent / 任务类型 / 输出语气三个下拉，任务描述、相关上下文、约束条件三个输入框主要在这里写东西
右侧栏项目宪法、可引用文件、质量检查勾文件、核对缺项
下方结果区生成的 Prompt，以及复制、下载 Markdown、保存为素材三颗按钮生成后在这里取走

工作台顶部还有两颗：引用最近对话、清空。

#产出交给谁

生成时先选目标 Agent，不同预设会改写「执行对象」与「交付要求」两段：

目标 Agent生成时追加的定位交付要求
Codex在当前代码库中实现、验证并说明结果直接完成修改，最后说明改动文件、验证方式与剩余风险
Claude Code按现有工程风格完成代码修改先读相关文件，再做最小必要修改，最后给出测试结果
Cursor作为编辑器内任务指令使用给出清晰的编辑步骤、目标文件与需要保留的行为
通用 Agent交给任意 Coding Agent 执行输出可执行方案、必要修改与验证清单

#组装顺序

点「生成 Prompt」后，SLATE 按下表顺序拼装正式文本。空段落会被整段略过，所以生成结果里没有哪一段是占位的。

顺序段落填什么怎么写更好
1# 任务要做什么、为什么做、怎样算完成（必填）把验收标准直接写进任务里；只写"优化一下"最容易被自由发挥
2# 执行对象交给谁、让它怎么交付由目标 Agent 预设决定，可换预设
3# 工作方式先探索还是直接动手、要不要先审风险由「输出语气」决定：直接执行 / 谨慎审计 / 先探索再实现；并固定要求"阅读现有代码后再行动，优先沿用项目已有模式"
4# 项目宪法当前生效的宪法规则，逐条编号来自项目或全局那一份，见 项目、工作区与分项目配置；没有规则时不出现
5# 重点文件你勾选的文件路径清单给路径比粘贴正文更省 Token，外部 Agent 会自己去读
6# 已知上下文报错、接口约定、关键代码片段、最近对话摘要只放对方看不到的信息；这里的内容会原样带过去
7# 约束条件不能改什么、必须保留什么、要遵守哪些风格或流程与宪法互补：宪法管长期，这里管这一单
8# 交付要求由预设决定，另附固定两条固定要求：不修改与任务无关的文件、遇到已有未提交改动先理解并兼容；完成后说明验证命令或无法验证的原因

#任务模板

不想从空白开始，可以先选一个任务类型，它会预填任务描述与约束条件：

任务类型预填的骨架
功能实现实现 / 期望行为 / 验收标准；约束：遵循现有架构与风格、改动范围尽量小、完成后跑检查
Bug 修复问题现象 / 复现路径 / 期望结果；约束：先定位根因、不回滚无关改动、补上能覆盖该问题的验证
代码审查审查对象 / 重点关注；约束：按严重程度列问题，每条带位置、风险与修复建议
重构整理重构目标 / 保持不变的行为 / 希望改善的问题；约束：外部行为兼容、不引入大型新依赖、沿用既有模式

模板只在对应输入框为空时填入，不会覆盖你已经写好的内容。

#输出语气

「输出语气」只影响生成结果里 # 工作方式 那一段，与任务类型互不干扰：

输出语气生成时写进 Prompt 的那句
直接执行请直接进入执行，不需要长篇方案铺垫
谨慎审计请先审计风险和边界，再做修改
先探索再实现请先给出 2-3 个可行方向，再选择最稳妥方案执行

三种语气都会附上同一句要求：阅读现有代码后再行动，优先沿用项目已有模式。

#生成结果长什么样

结果就是一份按上面顺序拼好的 Markdown，段落用 # 标题分隔：

text
# 任务
修复登录接口在密码为空时返回 500 的问题，修复后接口应返回 400 与明确错误码。

# 执行对象
交给 Claude Code 按现有工程风格完成代码修改。

# 工作方式
请先审计风险和边界，再做修改。
阅读现有代码后再行动，优先沿用项目已有模式。

# 项目宪法
1. 改动必须保持现有代码风格，不做顺手重构
2. 新增依赖前先确认项目里已有等价实现

# 重点文件
- backend/routers/auth.py

# 约束条件
不要改动返回体的字段名，前端已在依赖。

# 交付要求
请先阅读相关文件，再执行最小必要修改，最后给出测试结果。
不要修改与任务无关的文件；遇到已有未提交改动时，先理解并兼容它们。
完成后说明验证命令或无法验证的原因。

拿到手就是正式文本，可以直接整份贴给外部工具，不需要再补前言。

#宪法从哪来

右侧栏的「项目宪法」显示当前生效的那份规则，点「插入项目宪法」会把它们按条编号写进约束条件。规则来自项目自己的 .slate/config.json；项目没写则用全局那份，切换项目时右侧栏会跟着换。完整口径见 项目、工作区与分项目配置。

#与磨墨模式的分工

两者都在"把想法变成文本"，差别在起点：

磨墨模式提示词工厂
起点一句粗糙想法，还不知道具体要什么任务已经明确，只是要一个交付格式
做什么AI 三段式追问（接墨 → 磨墨 → 收墨），一次问一个，把缺口问出来把已知信息填进固定骨架，拼成正式文本
产出结构化任务书（墨稿）：目标 / 受众 / 交付物 / 验收标准 / 边界 / 建议路径 / 遗留问题一份可以直接交给外部 Agent 的 Prompt
下一步送入目标模式执行、投到白板推演、存为模板复用复制、下载或存为素材，交给外部工具执行

分不清时看一句话：还说不清要什么，去 磨墨模式；已经说得清了，来工厂。

#与目标模式的分工

目标模式让 SLATE 自己动手：它有自己的工具（读写文件、跑命令、查 Git），按六阶段闭环跑到验证通过为止，见 Agent Autopilot 与目标模式。提示词工厂不执行任何东西，它产出的是给别人执行的 Prompt——你想用 Claude Code、Codex 或 Cursor 来干活，就用工厂。

#生成后怎么用

  1. 逐段核对：生成结果显示在下方，从 # 任务 往下看一遍，重点检查验收标准与边界有没有漏。
  2. 复制 / 下载 / 存素材：结果区右上角三颗按钮分别是复制、下载 Markdown、保存为素材。素材会进你的提示词素材库，下次可以直接取用。
  3. 迭代：改一处输入再点一次「生成 Prompt」即可——输出是整份重新拼的，不会叠加。想推倒重来点「清空」。

右侧的「质量检查」会在你写的过程中实时给四项提示：任务是否足够明确、是否包含上下文或文件、是否声明了约束边界、是否选了目标 Agent。四项全亮不保证结果一定好，但缺项通常意味着这份 Prompt 还得回来补。

两个速记入口：「引用最近对话」把当前会话最近几条消息摘要塞进已知上下文；「插入勾选文件」读取右侧勾选的文件内容（一次最多 8 个，每个取前 6000 字符）。文件列表读的是当前项目目录，没打开项目时会提示你先打开项目。

最该写清的是验收标准与边界

外部 Agent 最怕两件事：不知道什么时候算干完，不知道哪里不能碰。

  • 验收标准写成可判定的事实："npm test 全绿"比"测试通过"清楚；"接口返回字段与签名不变"比"保持兼容"清楚。
  • 边界写成明确的禁令与保护："不要动 src/legacy/ 下的文件""保留现有公共 API 签名""不新增依赖"。
  • 顺带写清不做什么：说明"这次只改这一个文件"，比让 Agent 自己猜改动范围安全得多。
