## 任务清单是什么

目标模式跑多步骤任务时，模型会先建一份 TODOLIST，把大任务拆成可核对的小项，再逐项推进。这份清单不是装饰：未全部了结之前，模型不被允许宣称完成。

清单按对话隔离——每条会话各有一份，互不干扰，重开这条会话时还在。

## 清单面板怎么看

清单实时显示在消息区右侧栏：

- 头部报 `任务清单 {done}/{total}`，旁边补上「受阻 n」与「进行中 n」，并有一条进度条。
- 每一项带状态标记：待办、进行中、已完成、受阻。
- 每完成一项或一批，模型会立即同步状态，进度不必等收尾才更新。

顶栏的「任务清单」按钮可以整栏收起，把宽度还给消息区，再点一下展开。折叠之后进度不至于彻底隐身——按钮悬停会报 `{done}/{total}`。这一场没有清单时按钮置灰。折叠状态记在你本机：刷新、重启都保持，清单继续往下跑也不会擅自把栏撑回来。

## 清单由谁建、状态怎么变

清单不是你手动维护的东西。目标模式下遇到多文件、多步骤、排查或实现类任务时，模型会先建清单再动手；简单的单步任务会跳过清单直接做，所以看不到清单也是正常的。

每一项的状态随执行推进变化：

| 状态 | 含义 |
|---|---|
| 待办 | 还没轮到 |
| 进行中 | 正在做这一项 |
| 已完成 | 做完了，并且验证过 |
| 受阻 | 被外部条件挡住（缺依赖、等确认、环境不具备），模型会在正文里说明原因 |

全部条目了结之前，模型不被允许写收尾汇报；系统会把剩下的条目念回给它，催它继续推进。

## 待办与移动端

手机端底部有「待办」Tab（面板标题「待办 / 定时」），可以查看、新建、立即运行、删除定时任务；在电脑上建的任务，手机打开就是同一份列表。详见 [移动端遥控与局域网访问](./18-mobile.md)。

## 定时任务是干什么的

定时任务 = 一条预设提示词 + 一个触发时机。到点后由 SLATE 本地执行，把提示词交给指定模型跑一遍，结果落成一条独立会话——不需要你守在旁边，也不占用你正在用的那场对话。

新建一条任务需要四样东西：名称、提示词（到点后发给模型的那段话）、模型、模式。

## 新建一条定时任务

入口在聊天输入框左侧的 ＋ 菜单里（选「定时任务」），面板标题是「定时 / 事件任务」；手机端在底部「待办」Tab 点「＋ 新建」。

1. 填**任务名称**，它会出现在那次执行生成的会话标题里，写成能一眼认出的名字。
2. 写**提示词**：到点发给模型的那段话，写清要它产出什么。
3. 选**模型**：下拉里按国产 / 国际 / 本地 / 自定义分组，默认是你当前用的模型。
4. 选**模式**：每天 / 单次 / 间隔，再填时间点或间隔分钟数。
5. 点「+ 添加任务」，任务出现在下方列表里，随时可以停用或删除。

## 无人值守的提示词怎么写

定时任务每次都是新会话，没有前文可以依赖；执行时的系统提示也要求模型直接、完整地执行指令并输出结果，不要反问。所以提示词要自包含：

- **写清产出格式**：例如"用 Markdown 列出三块：昨天完成的事项、未完成的事项、今天的建议顺序"。
- **写清信息从哪来**：例如"读工作目录下的 TODO.md 与最近的 Git 提交记录"，而不是"接着上次说的继续"。
- **不要写需要你回答才能往下走的分支**——到点时没人回应它。
- **长度与结构写死在提示词里**，否则输出长短全凭模型当天的状态。

## 三种调度方式

| 调度方式 | 怎么算时间 | 适合什么 |
|---|---|---|
| 单次 | 指定一个时间点，只执行一次 | 一次性的提醒或一次性汇总；跑完任务自动停用 |
| 每天 | 指定一个时间点，每天执行；今天这个点还没到就等，到了且今天没跑过就跑 | 每日汇总、每天收工前的例行检查 |
| 固定间隔 | 每 N 分钟执行一次（默认 60 分钟，最小 1 分钟） | 需要反复盯着的短动作，比如隔一段时间看一眼构建状态 |

## 事件驱动触发

除了看时钟，任务还可以被事件推着走：事件发生时自动执行，结果同样归档成独立会话。三种事件来源：

| 事件 | 触发条件 | 可配置项 |
|---|---|---|
| 文件变更 | 监听路径下有文件被新建或修改 | 监听的文件 / 目录路径（每行一个，不填按任务所属项目的根目录）；冷却时间 |
| Git push 检测 | 指定仓库的 HEAD 发生变化 | 仓库路径；冷却时间 |
| Webhook 接收 | 外部系统向该任务的回调地址发起请求 | 密钥（用于校验来源，可选；请求正文会作为上下文注入提示词） |

冷却时间是最小触发间隔（默认 60 秒，最小 10 秒），目的是防止一次批量改动把任务反复刷起来。事件任务的提示词里会自动附上触发上下文——变更的文件、最新提交、Webhook 内容——所以模型知道"这次是被什么叫起来的"。

:::note 事件任务是"配置一次、长期挂着"
事件类型与监听路径随任务一起保存，改完即生效。文件变更与 Git 检测在 SLATE 启动时会先记一份当前快照，所以刚启动不会把之前的历史改动当成新事件误触发。
:::

## 结果去哪了

每次执行都会新建一条独立会话，标题带前缀与时间：

```text
[定时] 每日汇总 · 09-25 09:00
[事件] 构建看门 · 09-25 14:32
```

会话落在任务所属的项目名下——任务是在哪个项目里建的，结果就挂在哪个项目，切到别的项目后按项目筛选也不会错认。点进会话就是完整的提示词与模型回复。

## 怎么管理

任务列表里每一行都能看到：调度方式 · 所用模型 · 上次运行结果（跑过会写运行时间，失败会直接写原因，没跑过显示"尚未运行"）。

- 勾选框启用 / 停用，随时挂起而不必删除。
- ▶ 立即运行，不等下一次到点；已经在执行的任务不会被重复触发。
- × 删除任务。

## 什么时候不会执行

定时任务由本地调度器执行，所以有几个边界值得先知道：

- 只有 SLATE 在运行时才会到点执行。应用关闭期间不会执行；重新打开后，当天时间点已过且今天还没跑过的任务会补跑一次。
- 所用模型必须已经配置好 API Key，并且必须是 OpenAI 兼容的模型。拿不到 Key 或模型不兼容时，原因会写进任务状态，不会静默失败。
- 如果「设置 → AI 辅助功能」里关掉了「定时与事件任务」，任务不再执行；触发记录仍保留，状态里会写明是被这一项关掉的。详见 [设置与安全审批](./19-settings.md)。

:::tip 定时任务适合什么，不适合什么
**适合**：不需要你中途拍板的固定动作。汇总昨天的进展、定时检查仓库状态、隔一段时间看一眼构建结果、有文件变更就提醒——这类任务模型一次答复就能收尾。

**不适合**：需要你上来做选择的长任务。定时任务不会中途停下来问你，也不会等你确认再继续。把需要决策的部分写成"列出选项、说明各自代价"，把决定权留给自己，比让它替你拍板稳妥。
:::
