同一件事干到第二遍，你又要重申顺序、口径和踩过的坑。Actions 就是治这个的：把「干某件事的必要流程」提前写成一份说明书，模型在需要时自己去读、照着推进，你不必每次都交代一遍。

## Actions 是什么

一份 Action 就是一份流程说明书。它写清三件事：这件事什么时候该做、要按什么顺序做、做成什么样算过关。

写好之后，模型在智能体态下会先看到一份 Action 目录（每条只有 id、名称、一句话描述与适用时机），判断这次任务跟某份说明书吻合时，再读全文、按步骤实际执行。流程由你定义，模型只负责照做。

## 跟 Skill 的区别

两者都放在本机数据目录里、都在同一处管理，但回答的是不同的问题。

| 对比项 | Action 流程说明书 | Skill 技能 |
|---|---|---|
| 本质 | 可执行的步骤约定 | 知识与角色 |
| 回答的问题 | 这件事该按什么顺序做 | 这类事该怎么做、以什么身份做 |
| 内容形态 | 有序步骤，每步可注明建议工具与验收点 | 一篇说明文档 `SKILL.md` |
| 怎么用 | 模型检索目录 → 读全文 → 按步骤实际执行 | 写进 Skill 后，聊天中 `@` 提及即注入上下文 |
| 上限 | 遵循严格的书写格式，写坏会报出行号 | 文档形式，写法自由 |

一句话：Skill 让模型「懂」，Action 让模型「按你的顺序动手」。两者可以同时用。内置工具与技能的完整清单见 [内置工具与技能](./08-tools-skills.md)。

## 文件放在哪

一份流程一个文件，文件名去掉 `.yml` 就是它的 id（例如 `weekly_report.yml` 的 id 是 `weekly_report`）。id 只允许小写字母开头的 `a-z0-9_-`，最长 48 个字符，不必在文件里再写一遍。

- 全局那份：本机所有项目共用。
- 项目那份：放进当前项目的 `.slate/actions/` 里，同名时顶掉全局那份。

不确定放哪就先放全局，需要时再在项目里覆盖一份。

## 字段怎么写

一份说明书由下面几个字段组成，都是给人写、给模型读的：

| 字段 | 写什么 | 模型靠它判断什么 |
|---|---|---|
| `name` | 流程名，不超过 40 字 | 目录里认人 |
| `description` | 一句话说明，不超过 120 字 | 这份说明书值不值得点开读全文 |
| `when` | 什么时候该套用，不超过 200 字 | 这次请求要不要按这份流程走 |
| `inputs` | 开工前要向你拿的输入项，最多 8 项 | 先问你什么，再往下做 |
| `steps` | 步骤清单，1 到 24 步 | 按什么顺序做、该调哪个工具、怎么算过关 |
| `output` | 产出要求：格式与落点 | 最终交付成什么、放到哪 |
| `tags` | 标签，最多 8 个，单个不超过 24 字 | 检索时匹配关键词 |

`inputs` 每一项可以写：

| 键 | 说明 |
|---|---|
| `key` | 输入项的名字，小写字母开头，只能用 `a-z0-9_` |
| `label` | 展示给人看的名称，不写就用 `key` |
| `type` | `text` / `number` / `textarea` / `select` 之一，不写按 `text` |
| `required` | 只能写 `true` 或 `false` |
| `options` | 仅 `select` 需要，最多 20 项 |

`steps` 每一步可以写：

| 键 | 说明 |
|---|---|
| `title` | 这一步做什么，必填，不超过 60 字 |
| `tool` | 建议使用的工具名，例如 `git_tool`、`doc_write` |
| `detail` | 这一步的具体要求，多行正文用 `|` 字面量块 |
| `check` | 这一步的验收点，不超过 200 字 |

`output` 里，`format` 写产出的文件或正文格式；`destination` 只能写 `message`（留在对话里）、`file`（写文件）或 `board`（回白板）；写 `file` 时必须同时给 `path`。

## 一份最小的可抄示例

```yaml
name: 周报整理
description: 把这一周的提交与进展整理成一份周报
when: 用户要求写周报、整理本周进展时
inputs:
  - key: scope
    label: 统计范围
    type: text
    required: true
steps:
  - title: 收集素材
    tool: git_tool
    detail: |
      读取本周的提交记录与变更统计，按模块归类。
    check: 每个模块都有对应的提交出处
  - title: 起草周报
    detail: 按「本周进展 / 风险 / 下周计划」三段起草，每段不超过五条。
  - title: 落盘
    detail: 写入 docs/weekly/ 目录，文件名带本周日期。
output:
  format: markdown
  destination: file
  path: docs/weekly/weekly.md
tags:
  - 周报
```

把这份文件存成 `weekly_report.yml`，它就会出现在 Action 目录里。

## 书写格式的硬约束

Action 用的是一套精简的 YAML 子集，只支持你真正需要的写法。超出范围的写法不会被「猜着解释」，而是直接拒收并告诉你出在第几行。

- 缩进固定 2 个空格，最多嵌套两层。禁止 Tab 缩进。
- 数组用块式写法：每行一个 `- `，同一层的 `-` 必须对齐。
- 多行正文用 `|` 或 `|-` 字面量块，块内缩进要一致。
- 布尔值只认 `true` / `false`。
- 不接受锚点与别名（`&`、`*`）、多文档分隔符（`---`）、折叠标量（`>`）、流式写法（`[]`、`{}`）与未闭合的引号。
- 单份文件上限 64 KB；所有 `detail` 正文合计不超过 20000 字。

校验报错的形式是「第 N 行：原因」，改了再存即可。

:::warning 别把密钥写进说明书
Action 的内容会长期进入模型的系统提示，等于把 Key 直接摆给模型看。需要凭据时，写「引用某个环境变量或文件位置」，不要写明文。面板会对疑似凭证给出提醒，但不会替你拦下。
:::

## 模型怎么用它

在智能体态下，模型会先拿到一份 Action 目录，最多列 20 条；超出的部分只报数量，并告诉它用 Action 检索去看全部。它的典型动作是三步：检索 → 读全文 → 按步骤执行。在对话态下没有工具可用，整份目录都不会注入。

需要强调的一点：**读到流程不等于做过流程**。步骤里标了建议工具的，模型仍要真的调用工具完成；它不会因为「读过这份文件」就宣称已经做完了。

## 手动把流程发进对话

不想等模型自己检索，你也可以直接点名：

- 在输入框输入 `@`，从候选里选一份 Action，整份流程会注入这条消息。
- 注入有 6000 字上限，超出的部分会被截断，并提示模型用读取工具取全。
- 提及用的是 id（文件名），中文名与标签只作为搜索别名。

适合的场景是：你已经知道该用哪份流程，只想让它这一次严格照做。

## 在白板上跑这条

打开黑板 →「工作流」显示模式，每一份 Action 都会成为卡片墙上的一张卡，卡面写着共几步、几项输入、谁写的、产出落到哪。卡上的「跑这条」会以 @提及 的方式把它发进当前对话，「看步骤」可就地展开步骤清单，「置顶」把常用的排在前面。

工作流视图同时还能看到这次运行走到了哪一步，细节见 [白板式逻辑链](./12-whiteboard.md)。

## 在设置页编辑

顶栏「扩展」→「Actions」栏，点「＋ 新建 Action」，或点已有条目进编辑器。

编辑器边写边校验，报错会指出第几行、什么原因；校验没过就保存不了。编辑器顶部会写明你正在改的是哪一份：全局那份，还是某个项目的覆盖版。

## 让模型代写

你也可以直接让模型把流程写下来——前提是它必须按要求声明 `author: model`，面板据此给这份文件打上「模型代写」的标记。

在「询问」权限模式下，写入前会弹窗把原文给你看，你点允许才落盘；切到「自动」或「越权」则不再弹窗。无论哪一档，格式校验都在写入前执行，不合格的内容进不来。

:::tip 最划算的一份 Action
挑「你已经跟模型重复交代过两遍以上」的流程写。写一次，之后每次它自己读、自己照做，省下的是往后每一次的复述。
:::

## 留底与回滚

每次覆盖或删除之前，SLATE 会先把原文留底，每份最多保留 5 个版本。编辑器里的「历史版本」可以查看任意一版并一键回滚；回滚本身也是一次写入，会先校验再落盘。

留底跟着落点走：项目那份的历史留在项目自己的目录里，不会与全局那份混在一起。

## 分项目覆盖

在打开的某个项目里放一份同 id 的说明书（`项目目录/.slate/actions/<id>.yml`），它会顶掉全局那份，其他流程照旧可见，不会「一进项目流程就消失」。

列表里会标出哪一条是「本项目」那份，编辑器也会写明现在改的是哪一份。删掉项目那份，同名流程自动回落到全局那份——这不是把流程整个删了。项目与全局的关系详见 [项目、工作区与分项目配置](./14-projects.md)。

## 写坏的文件不会凭空消失

改坏一份文件，它不会被静默忽略：设置页的 Actions 列表里会连它一起列出，并附上「第 N 行：原因」；模型那边拿到的工具返回也会告诉它哪几份暂时不可用；工作流视图的卡片墙上则会提示有几份说明书解析失败。看到这类提示，照着行号改回去即可。
